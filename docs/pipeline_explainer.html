em-pipe · FIB-SEM processing

How em-pipe Works

The microscope gives us thousands of thin slices of a brain, each photographed as a mosaic of overlapping pictures. em-pipe turns that pile of pictures into one clean 3D volume you can scroll through in neuroglancer, with the same brightness and contrast in every volume we make.

Each part starts with the simple version. Panels marked + More detail open up what the code actually does, for anyone who wants to follow a run or read its QC plots.

Goes inRaw tiles: a 3×3 or 2×2 grid of pictures per slice, 8 nm pixels, 16-bit values
How many35h has 17,689 slices; A1001 has 487
Comes outOne volume, greys 0 (black) to 255 (white), with zoomed-out copies for fast viewing

Stage 1

Take stock of the raw pictures

Check the raw files check

Before doing anything else, em-pipe makes a list of every picture: which slice it belongs to, which tile of the grid it is, and when it was taken. It flags problems such as half-written files, missing tiles, long pauses and restarts. It also notices when the tile grid changes during the run (for example from 3×3 to 2×2 tiles). Each stretch of slices with one tile layout is called a segment, and segments matter a lot later on.

Make small previews preview

Every tile is shrunk 16 times (8 nm pixels become 128 nm pixels) into a thumbnail, with a few brightness numbers per tile, such as the median and percentiles of its tissue (resin left out). Later steps use these thumbnails when they need a quick look at everything without reading the full-size data again.

Stage 2

Put the pieces together

Stitch the tiles of each slice stitch

Neighbouring tiles overlap a little, like photos for a panorama. em-pipe finds the same small features in both tiles where they overlap and works out where each tile sits so the features line up.

Line the slices up with each other align

The sample drifts slowly while it is being imaged, so each slice is matched to the next few slices and all the shifts are solved together. Where the tile layout changes between segments, it also works out how the two layouts fit, including a gentle warp where a simple shift is not enough.

More detail: how stitch and align work

Stitch uses SIFT feature matches. It first searches whole tiles shrunk 8 times to find the overlap, then matches the overlap strips again at higher resolution. One least-squares solve over all tile pairs gives each tile's position (by default an affine transform held close to rigid). It does this on every 50th slice of a segment. Where a tile moves by more than 5 px between two of those, it also stitches the slices in between, halving the gap each time, so a sudden jump is placed at the right slice instead of being smeared over 50 slices.

Align matches each slice with its next few slices, keeps only matches that agree (RANSAC) and then finds one transform per slice that fits all the matches at once (a global sparse least-squares solve, as in Janelia's render pipeline). Solving globally avoids the slow random walk you get by chaining one slice to the next. At a change of tile layout it first fits one transform between the two layouts; if a median mismatch of more than 5 px is left, it adds a smooth warp to the slices before the change.

Stage 3

Even out the brightness between and within tiles

Even perfectly placed tiles do not match in brightness. These steps make the whole slice look like one picture instead of a patchwork.

Correct the uneven lighting inside each tile shading

The microscope's picture is a little brighter in some parts of a tile than others (in 35h, about 8% darker towards one side of the right-hand tiles, the same in every slice). Averaged over many slices, the anatomy averages out and that pattern is left, so em-pipe measures it for each tile position and segment (a flat-field) and divides it out.

Compare tiles where they overlap overlaps patchgrid

Where two tiles overlap they show the same tissue, so they should have the same brightness. em-pipe compares them pixel by pixel in every slice and writes down how one tile's values relate to the other's. With patchgrid, each tile is also cut into a grid of patches, which catches the leftover differences near tile edges and corners that the flat-field misses.

Balance the tiles intensity

From all those comparisons, em-pipe gives each tile a small brightness correction so that all the tiles of a slice sit on one shared scale with no visible seams. Everything after this point works on that shared scale.

More detail: tile balance and per-slice jumps

The relations

The overlaps step reads each overlap from both raw tiles in every slice, divides out the flat-fields, shrinks it to 32 nm and fits a straight line through the pixel pairs, A = gain × B + offset, throwing out pairs far off the line. Tissue and resin both count: resin is a clean reference for the bright end. With overlaps.patch_grid: 8 (our setting) each tile is also cut into 8×8 patches and there is one relation per pair of overlapping patches; patchgrid turns those into a smooth brightness map inside each tile, after Janelia's tile intensity correction.

The solve

For each slice, intensity finds one gain g and offset o per tile so that, in every overlap, gA·A + oA = gB·B + oB as nearly as possible. The equations are weighted by how many pixels each overlap has; the gains are solved as logarithms and pulled weakly towards 1, and the average gain is fixed at 1 and the average offset at 0. Each tile's corrected values u (flat-fielded, patch map applied) then go onto the slice's common scale:

common value = g × u + o

Every window from here on is a window on the common scale. Our configs solve every slice on its own (balance_smooth_slices: 1).

Per-slice jumps

Raw tiles jump up or down by 1–2% of the display range from one slice to the next, while the tissue itself changes slowly. So the difference between a tile's median and its running median over 51 slices is taken as that slice's jump, and the window moves with the jump. With per_slice: slice (our setting) one jump is used per slice, the median over its tiles, so the tiles stay matched.

Stage 4 · new in November 2026

Set brightness and contrast to the lab standard

The raw values are 16-bit numbers. The final volume has greys from 0 to 255. Somewhere we have to choose which raw value becomes black, which becomes white, and how everything in between is spread out. That choice is called the window. Its position sets the brightness and its width sets the contrast: a narrow window stretches small differences into big ones.

The idea in one line

Photographers put a grey card in the shot and set the exposure so the card always looks the same. We use neuropil as our grey card: we set every volume's window so its neuropil comes out the same as in 35h.

Why neuropil?

Matching on "all tissue" depends on what happens to be in the picture: a slice with lots of cell bodies, gut or empty resin gives a different result from one full of neuropil, even if the staining is identical. Neuropil (the dense tangle of neurites, including fibre tracts) looks much the same in every volume and is present in almost every slice, so it makes a fair yardstick.

Find the neuropil refmask

A small trained classifier looks at the 128 nm thumbnails in squares of about 2 µm and decides, square by square, whether it is neuropil or not. It goes by texture: neuropil is a fine, even texture, while cell bodies are coarser with smooth insides. It was trained on example boxes that a person checked by eye, one by one. The mask only decides where to measure. It is never applied to the image.

More detail: the classifier and its training boxes

Each tile's thumbnail (raw values, before any contrast step) is cut into 16×16-pixel squares, about 2 µm across. For every square the code computes 47 numbers, all chosen so they do not change when the brightness or contrast of the picture changes, or when the picture is rotated:

  • how much texture there is at six scales, from very fine to coarse, relative to each other, and a fine-versus-coarse texture score;
  • the square's brightness and texture compared with the rest of the tile's tissue, and how many of its pixels are very dark or very light;
  • whether its structures are line-like or blob-like (coherence, roundness at about 0.4 and 1 µm);
  • each of those again, averaged over the surroundings (about 4 and 8 µm), so a square is judged in context.

The model is a set of 150 small gradient-boosted decision trees (written in plain numpy, pipeline/boost.py). Squares with a probability above 0.5 are candidates; a connected area is kept only if it has at least 12 squares and contains a "seed" whose wider average is above 0.8, and holes of up to 4 squares are filled. Squares that are mostly resin never count.

Training boxes. 10 µm boxes on 35h, 37i and A1001, proposed by the tool and then checked by a person on pictures like the one below, box by box (19 November 2026). 101 boxes were confirmed (53 neuropil, 48 cell-body rind) and 4 rejected: one wrong box each in 35h and 37i, and two in A1001 that sat on the oesophagus. The rule is that "other" boxes are cell bodies only, never gut, oesophagus or trachea. The confirmed boxes and the rejected ones are recorded in pipeline/refmask_neuropil_labels.json.

Known weakness. Tightly packed small cell bodies (2–3 µm, little contrast in the nucleus) can look like neuropil at this resolution and get included.

Measure the neuropil refstats

On a sample of slices (by default every 32nd slice of each segment; every 64th for our large volumes), em-pipe reads the full-size tiles, applies exactly what the final render will apply (decurtaining, the lighting fixes and the tile balance) and takes the histogram of the neuropil pixels. From that histogram it keeps the median (the middle value) and the 5th and 95th percentiles. The gap between those two is the neuropil's p5–p95 width, a simple measure of its contrast.

More detail: what refstats measures
  • Which slices. Every N-th selected slice of each segment, plus each segment's last (refstats.every: 32 by default, 64 for 35h and 37i).
  • Which values. Full-resolution tiles, decurtained when render will decurtain them, divided by the flat-field, with the patch map applied, then put on the common scale with the tile's gain and offset (g × u + o). So the numbers describe exactly the values the window will see.
  • Which pixels. Inside the neuropil squares, shrunk by one square all round so the edge of the neuropil does not count. Optionally only inside a region box (A1001 uses one to leave out nerve cord that the other volumes do not have).
  • Pooled per slice. The neuropil pixels of all tiles of the slice (every 4th pixel at 8 nm) go into one histogram, which gives the median and the percentiles 1, 5, 25, 75, 95 and 99. The width is p95 − p5.
  • Cross-check. lc32, a local-contrast measure (the average standard deviation in small windows at 32 nm), per square and then the median over squares. It is reported but not used to set the window.
  • For the clipping estimate. Percentiles of all the tissue (every 8th pixel), so the QC can predict how much tissue a window will turn pure black or white.
  • A sample with fewer than 20 neuropil squares does not count.

The standard

Every volume is set so its neuropil has a median grey of 150 and a p5–p95 width of 130 greys.

Where those numbers come from: 35h, as it was already rendered, had a neuropil median of 148 and a width of 143. The median is rounded to 150. The width is set a little narrower, at 130, which gives slightly less contrast than 35h had. That was decided on 20 November 2026, after first trying 140:

  • Less tissue turns pure black or white. Over the whole volume, the clipped tissue goes from 1.75% to 1.3% in 35h (most of what is left is its pitch-black granules, which stay black at any width), from 0.5% to 0.2% in 37i and from 0.3% to 0.15% in A1001.
  • Nothing is lost in the middle greys. A single 8 nm pixel is noisy by 5.5–11 greys. Storing whole greys adds a rounding error of about 0.29 grey, which makes the total noise less than 0.3% larger at any of these widths. So spreading the neuropil over 130 greys instead of 140 doesn't merge differences you could see.
  • The CLAHE copies look the same. After CLAHE, widths of 130, 135 and 140 look practically identical.
More detail: width 130 and 140 side by side

Fast changes from the tissue, slow changes from the neuropil intensity, window: reference

Two kinds of change need different handling.

  • Fast changes. The overall brightness of the raw pictures wobbles by about 1% over tens of slices, which would be 15–30 greys on screen, and jumps a little from one slice to the next. The window follows these slice by slice, from all the tissue in the slice, which the previews measure in every slice. This is what the earlier windows did too.
  • Slow changes. On top of that, two things follow the neuropil, slowly: the window's width (contrast) and a brightness shift that puts the neuropil's median at 150. Both come from the sampled slices and are smoothed over up to about 2,000 slices, starting afresh at every segment change. Where the neuropil really does change faster, they follow faster (below).

Why slowly? The neuropil is only measured on sampled slices, and its numbers vary a little from sample to sample as the view changes. Following each sample would add flicker; following them slowly corrects drifts without ever causing flicker. Why start afresh at each segment change? Because the raw pictures really do change there: in 35h the neuropil's raw width jumped by 27% where the tiles went from 3×3 to 2×2.

When the neuropil changes quickly: follow faster adapt: true

Smoothing over 2,000 slices is right when the neuropil drifts slowly, but sometimes it changes faster for real: the microscope settles for a few hundred slices after a pause, or a setting changed mid-segment. A long window smooths such a change away and leaves those slices off target, most of all at the start of a segment, where the window can only look forward.

So the window adapts. It first measures how much the samples scatter when nothing is changing (the difference between neighbouring samples). Then, at every slice, it starts from a short window of a few samples and makes it longer, step by step, for as long as the longer window still agrees with the shorter ones within that scatter (2.5 times its expected error). Where the neuropil is steady it ends up with the full 2,000 slices, the same as before; where it changes, it stays short and follows. The QC plot shades those faster stretches orange.

More detail: how far the window shortens, in numbers

Scatter between samples. The typical difference between neighbouring sampled slices, divided by √2, pooled over the volume: for 35h 0.52% for the width and 3.7 greys for the brightness shift; for 37i 0.4–0.5% and 1.2 greys.

Window lengths. From about 1.5 sample spacings (192 slices when every 64th slice is sampled) up to 2,000 slices, in steps of √2. A window wholly inside the segment takes the median of its samples. A window cut off by the segment's start or end fits a straight line instead (robustly, so one odd sample can't tip it), so a settling at the edge isn't flattened.

How often it shortens. In 35h the width followed faster in 15 stretches, 31% of the slices, mostly where the first segments settle; the brightness shift in 3 stretches (2%). In 37i: 11 and 5 stretches (22% and 7%).

Settings: intensity.reference.adapt: true (default) and adapt_sigmas: 2.5. The QC file intensity_reference_*.json lists the scatter (sample_noise) and every faster stretch with its shortest window (faster).

More detail: the window maths

All values are on the slice's common scale (see stage 3). A value v becomes the grey

grey = 255 × (v − L) ÷ W

clipped to 0–255. W is the window's width and L its low end.

Width (contrast)

W = 255 × c ÷ 130

where c is the neuropil's p5–p95 width, smoothed along z. Then the neuropil's p5–p95 spans exactly 130 greys.

Low end (brightness)

L = M + J − a

  • M: the slice's all-tissue median on the common scale, as the earlier median window placed it (tissue medians from the previews, running median over 51 slices). This is the fast part that follows every slice.
  • J: the slice's jump (stage 3).
  • a: the slow brightness shift. At each sampled slice with neuropil median m, the shift that would put that median at exactly 150 is

a = 150 × W ÷ 255 − (m − M − J)

Check: with that shift, the neuropil median's grey is 255 × (m − M − J + a) ÷ W = 150.

How c and a are smoothed

Within each block (a segment, or part of one when a breaks entry splits it, as at A1001's z 127, where the slice interval and the raw neuropil changed mid-run), the sampled values of c and of a each get a running median over up to 2,001 slices (±1,000; shorter where the samples change faster than their scatter, see "follow faster" above), are interpolated linearly between samples (held at the block's ends), and then get a running mean over 129 slices so there are no kinks. Settings: intensity.reference.per: slice, smooth_slices: 2001, adapt: true, adapt_sigmas: 2.5, ramp_slices: 129. With per: segment, c and a are instead the medians over the block's samples.

Back to each tile

The window L to L + W is mapped back through each tile's gain and offset, lo = (L − o) ÷ g and hi = (L + W − o) ÷ g, and written to work/intensity/levels.csv (one lo and hi per slice and tile), which render reads.

Stage 5

Make the volume

Apply everything in one pass render

Render reads every raw tile once and, for each one: removes curtains (when switched on), divides out the uneven lighting, applies the tile's brightness correction and window to get greys from 0 to 255, and places the tile where stitch and align said it goes. The tiles of a slice are joined into one picture and written into the volume (OME-Zarr format). Render first freezes its plan, so changing a setting halfway through a render cannot mix two versions in one volume.

Decurtaining, in short

The ion beam that cuts each slice leaves vertical stripes called curtains. When it is switched on, render removes them from each tile before anything else. If the microscope also recorded a second detector that hardly sees curtains (backscatter), the stripy part is swapped in from that detector instead of being filtered away. The neuropil is measured after decurtaining too, so the contrast is set on the same image that ends up in the volume. The curtain work has its own, fuller explanation: Decurtaining with the backscatter signal.

More detail: what decurtaining did to the neuropil numbers (37i)

37i's neuropil was measured twice on the same sampled slices, once on the plain tiles and once on the decurtained ones. The median did not change (ratio 0.9998). The p5–p95 width came out about 1% narrower overall and 2–3% in the early segments where the curtains are strongest: curtains are dark and light stripes, and they widen the histogram. A couple of slices with strong curtains (near z 5100 and 5750) had a much wider neuropil without decurtaining and a normal one with it. So a decurtained volume gets a window about 1% narrower, slightly more contrast.

The CLAHE copy

CLAHE is local contrast boosting. It splits each slice into small squares (256 pixels, about 2 µm, for our volumes) and stretches the contrast within each square separately, with a limit (1.5) so it does not blow up the noise. Membranes stand out everywhere, which helps with looking and tracing. The price is that a given grey no longer means the same thing in different places. That is why the CLAHE version is a separate volume, and the plain volume, with its consistent grey scale, is the one to use for measurements and for training models.

Zoomed-out copies pyramid

Finally, em-pipe makes smaller copies of the volume, each half the size of the last in every direction (averaging 2×2×2 blocks of voxels). neuroglancer shows the small copies when you are zoomed out and the full resolution when you zoom in, so scrolling stays fast.

Stage 6

Hand it over for segmentation

A copy in the format the segmentation team reads precomputed

The segmentation team's tools read "Neuroglancer precomputed", not OME-Zarr. The export makes that copy of every zoom level, with the same greys voxel for voxel (no compression loss). The voxels are grouped into shard files of 512 × 512 × 512, so a volume of terabytes is tens of thousands of files rather than tens of millions.

The export is written straight into the team's cloud bucket, as it is made. There is no local copy: each export is terabytes (35h's was about 10 TB; the shards are compressed losslessly, but electron microscopy images don't shrink much), too much to keep a spare copy of several volumes on the lab share. About 40 cluster jobs each write their own shards, so no two jobs touch the same file.

Safe to re-run, safe for what is already there

  • Progress is recorded. Each job notes every shard it has written in the volume's work folder, so a job that is stopped (time limit, network trouble) is simply submitted again and carries on. A shard that is noted but missing from the bucket is written again.
  • Nothing is replaced by accident. If the destination already holds a volume, the export refuses unless told to replace it, and even then only if the old one has exactly the same size and settings. In practice each new version gets its own name, so the team can switch over when they are ready.
  • The key stays put. The bucket's access key is a file on the cluster; the export only tells the storage library where it is, and never copies or prints it.

The older route, exporting to a folder on the lab share and then uploading it, still exists for small volumes or other destinations.

Words used here

Glossary

Slice (z)
One layer of the sample, cut away by the ion beam and imaged. Slices are numbered from 0 in the order they were taken.
Tile
One picture in the grid that covers a slice, named by row and column, such as 1-0.
Segment
A stretch of slices imaged with one tile layout. A new segment starts whenever the grid or tile size changes.
Block
What the window's slow smoothing restarts at: a segment, or part of one when the config adds a break.
Sampled slice
One of the slices refstats measures (every 32nd or 64th of a segment).
Neuropil
The dense tangle of neurites (axons and dendrites) between the cell bodies, fibre tracts included.
Common scale
The values of all tiles of a slice after each tile's gain and offset, so that they agree in the overlaps.
Window
The rule that turns raw values into greys: everything below its low end is black, above its high end is white, linear in between.
Grey
A value from 0 (black) to 255 (white) in the final volume.
Percentile
The 5th percentile (p5) is the value that 5% of pixels are darker than; p95 is the value 95% are darker than; the median is p50.
Jump
A small, sudden brightness change of the raw pictures from one slice to the next, which the window follows.
Flat-field
The map of how much brighter or darker each part of a tile is than average, from the microscope's uneven lighting.
CLAHE
Contrast-limited adaptive histogram equalisation: local contrast boosting, square by square.
OME-Zarr
The file format of the volume: many small chunks plus the zoomed-out copies, which neuroglancer reads directly.
Precomputed
Neuroglancer's other volume format, the one segmentation tools (CloudVolume and those built on it) read. The export makes it from the OME-Zarr volume, voxel for voxel.
Shard
One file holding a block of chunks (here 512 × 512 × 512 voxels), so a huge volume is a manageable number of files.
Bucket
A storage space in the cloud (Google Cloud Storage) that the segmentation team reads from.
Adaptive window
The smoothing of the neuropil numbers along z that is long (up to 2,000 slices) where they are steady and short where they really change.
